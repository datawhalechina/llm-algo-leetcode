# 08 评测集、推理负载与校准样本

## 学习问题

同一批问题可以用来检查回答质量，也可以用来测推理速度，但需要保存的配置和统计方式不同。有些量化方法还要用样本估计数值范围或优化量化参数，这些样本会参与方案选择，应与最终质量测试分开。

先区分三个用途，再看怎样准备一组能解释结果的请求：评测关心回答是否满足任务，性能测试关心在什么请求和到达条件下完成，校准则为特定量化方法提供代表性输入。

<a id="three-data-uses"></a>

## 用途决定保留什么

质量评测需要问题、参考依据、评分方法与失败处理规则。推理负载是在一次性能测试中实际发送的请求集合及发送方式，需要保留输入、生成设置、顺序与时间安排。校准样本则按量化方法的要求进入模型，供观察数值分布或调整量化参数；是否需要、需要哪些内容和多少样本，由所选方法决定。

| 用途 | 需要固定的内容 | 用来回答什么 |
|:---|:---|:---|
| 质量评测 | 问题与参考依据、输入模板、评分规则和集合成员 | 模型或RAG方案是否完成目标任务，哪些类别退化 |
| 推理性能测试 | 请求文本、分词器与模板、生成配置、到达方式和缓存条件 | 延迟与吞吐变化发生在什么负载下 |
| 量化校准 | 校准成员、模型与分词器、长度处理及量化配置 | 量化参数依据哪些输入确定，能否重新得到相应配置 |

<a id="evaluation-set-design"></a>

## 评测题要能解释总体分数

先按目标任务选择问题，再按语言、长度、难度或工具类型保留分类字段。设备支持问答可以同时包含工作日时间、周末条件、资料缺失和容易混淆的维修问题。只检查资料里直接出现的一句原话，会遗漏需要判断适用条件或说明信息不足的情况。

验证集用于选择提示、切块方式、量化配置等，最终测试集留作选择完成后的比较。问题、参考答案与判分结果按用途隔离；开放资料问答允许检索题目对应文档时，把这一条件写清。超时、格式失败和无法评分分别统计，再按预定规则计算分数，保留各类别样本数量和失败明细。

<a id="inference-workload"></a>

## 请求的长度和共享内容怎样影响测试

准备四条教学请求：R1与R2共享同一段设备说明，但问题不同；R3是独立短问答；R4包含更长的上下文。记录实际文本，应用目标后端的模板与分词器后统计输入词元。共享前缀也按实际送入的词元序列核对，模板或开头标记变化可能使原以为相同的内容失去前缀共享。

这四条请求的比例、顺序与重复次数会影响缓存和批处理。比较前缀复用时，说明是从空缓存开始，还是在指定预热后运行，并保留缓存重置方式；比较不同请求顺序时，分别保存它们，而不是只保留总请求数。输出同时记录最大生成限制、实际生成词元和结束原因，最大生成长度相同并不保证实际生成量相同。

<a id="arrival-and-failure"></a>

## 请求何时到达也属于负载

固定并发与固定到达速率控制的是不同条件。固定并发通常在一个请求完成后补入下一个，完成越快，后续请求发出也越快；按预定时间发送请求则让到达安排独立于完成速度，服务变慢时可能积累排队。选择哪种方式，要与希望模拟的场景对应，并记录实际发送时间和偏离计划的情况。

保存每条请求的编号、开始与结束时间、状态、实际输出和错误类型，再计算延迟、完成吞吐与失败比例。请求内容相同之外，发送器、预热、缓存状态和生成设置也需保持可比较；改变其中某项时就把它列为比较变量。指标起止位置和计量细节见[推理优化的请求路径与指标](../inference_optimization/01_request_path_and_metrics.md)，完整流程中的检索、准备和搬运耗时则在[性能优化](../performance_optimization/intro.md)中继续分析。

事件回放与统计可用[Part 02 · INF-REQUEST-LIFECYCLE](../../02_PyTorch_Algorithms/INF-REQUEST-LIFECYCLE_Inference_Request_Lifecycle.ipynb)练习；逐请求记录及汇总核验由[Part 02 · 66 单卡推理测量基线](../../02_PyTorch_Algorithms/66_Inference_Performance_Comparison.ipynb)继续。原始问题怎样选、实际词元长度怎样分布，仍在发送请求前按上面的数据要求检查。

<a id="calibration-samples"></a>

## 校准样本怎样代表实际输入

对于需要数据校准的量化方法，样本应覆盖计划使用的语言、任务与长度范围。例如目标服务包含长文问答，全部用极短闲聊校准，就需要额外检查长输入下的质量。采用同一模型的模板和分词器，记录截断、打包及实际输入词元；只保存“校准了若干条”，难以找回模型真正处理过的内容。

校准数据参与量化参数的确定，独立质量评测再检查量化后的模型。比较不同校准集时，固定其他量化条件，分别保存校准成员与生成的配置或权重，并报告目标类别的质量和运行成本。某些方法使用真实回答文本，另一些只需要提示或其他输入，按方法要求准备，避免把评测答案随意拼入校准输入。具体量化方法与误差解释参考[量化与压缩专题](../quantization_compression/intro.md)。

可以先用[Part 02 · 52 量化校准范围与裁剪](../../02_PyTorch_Algorithms/52_Quantization_Calibration_and_Error.ipynb)检查这一分工：缩放因子从校准数值估计，误差在独立验证数值上计算，用验证结果选择裁剪范围。这个数值练习帮助理解范围选择；真实语料是否覆盖目标任务，再按上述语言、长度和任务分布检查。

<a id="test-data-versions"></a>

## 怎样找回某次测试使用的请求

把数据成员、内容校验值、模板、分词器、生成与发送配置一起关联到运行记录。输入文件未变，但模板改变，送入模型的序列仍会变化；缓存预热和到达安排改变，也可能让同一请求集产生不同性能。保存这些差异后，再解释质量、延迟和成本的变化。
