# 06 从诊断到行动决策

## 页面目标

本节负责把 profiling 的证据链收束成行动：继续观察、深入排查、优化、还是回退。

本节的输出不是“最优方案”，而是带证据等级的下一步动作。只有问题定义、profile 证据和 benchmark 结果相互支持时，才应把优化提升为项目结论。

## 决策框架

1. 先确认问题类别：compute、memory、communication、experiment design。
2. 再确认证据是否足够稳定。
3. 再决定动作：
   - `keep observing`
   - `inspect deeper`
   - `optimize`
   - `revert`

## 状态与证据要求

| 状态 | 进入条件 | 输出 |
|:---|:---|:---|
| `inspect` | 现象已出现，但指标或证据不足 | 继续采集什么、验证哪个假设 |
| `optimize` | 瓶颈已有证据，准备修改目标变量 | 候选策略和预期代价 |
| `validate` | 对照实验显示收益，且质量和稳定性未回归 | 固定环境下的适用结论 |
| `revert` | 候选无收益、引入回归或无法复现 | 回退原因和后续替代方案 |

这里的状态描述分析流程，不等同于量化或推理项目中的 `accept / tune / reject`。两套状态可以在项目报告中同时出现，但含义必须分开。
