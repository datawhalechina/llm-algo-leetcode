本表登记部署实验使用的环境、候选身份、工作负载、结果路径和证据状态。安装与恢复命令见[实验 Quickstart](./quickstart.md)，跨专题 Profile 与隔离关系见[环境资产索引](../../gpu_environment_assets.md)，实际软件版本和硬件快照写入结果 JSON。

| 环境或角色 | 直接入口 | 可形成的证据 | 不能替代的证据 |

| 量化产物生成 | 40、53 使用 `Q-CUDA-MECHANISM`；82 另用目标后端检查加载 | 生成候选包，保留校准、质量和文件清单 | 目标服务后端的执行收益 |

## 推荐验证顺序

默认先做浮点单卡验证：CPU 契约检查 → 66 浮点基线 → 72 单卡候选 → 配置回归与交付检查。量化候选在浮点基线之外增加 82 产物准入与 67 部署对照，再用 83 比较量化服务配置；单实例容量或服务目标无法满足时，再进入 81 多设备分支。各分支按本次目标分别验证，Part 05 使用自己的输入与项目协议。

| 路径阶段 | 验证对象 | 通过条件 | 失败后的动作 |
|:---|:---|:---|:---|
| 公共准备 | CPU 契约与设备能力 | 候选身份完整，目标设备和后端没有已知阻断项 | 修复产物、输入协议或能力条件，不进入性能比较 |
| 浮点基线 | 66 浮点服务基线 | 固定请求能够重复完成，质量与服务指标可记录 | 修复环境、模型或请求协议 |
| 单卡默认路径 | 72 单卡候选 | 固定请求、设备与统计方式；模型、后端或精度的变化单独声明，并满足相同任务质量要求 | 保留失败日志，检查路径回退或容量边界 |
| 量化分支：产物 | 82 量化产物准入 | 文件、哈希、模型 revision、质量方向和加载器检查通过 | 拒绝产物或返回量化专题重新生成 |
| 量化分支：执行 | 67 量化部署对照 | 对照对应浮点基线，记录实际加载与计算路径、质量和服务指标 | 检查量化格式、后端支持与执行回退 |
| 量化分支：配置 | 83 量化服务配置回归 | 至少一组配置满足对应质量、容量和服务目标 | 调整配置或回退到上一稳定候选 |
| 公共复测 | 当前候选的配置回归 | 固定质量集与请求，配对检查配置变化后的延迟、吞吐、容量和失败率 | 调整配置或恢复上一稳定版本 |
| 多设备扩展 | 81 多设备候选 | 单实例不足证据明确，通信、状态交接和恢复结果完整 | 保留为待验证候选，补真实设备与后端结果 |
| 综合交付 | Part 05 独立项目 | 按项目协议验证候选的成本、降级、恢复和回滚条件 | 输出调优或拒绝决定，不以局部吞吐代替交付结论 |

## 部署结果增量字段

通用结果契约之外，部署证据至少增加以下字段：

| 字段组 | 必须记录的内容 |
|:---|:---|
| 候选身份 | 模型、revision、分词器、模板、产物 ID、文件哈希与配置 |
| 执行环境 | 设备、驱动、运行时、推理后端、实际数据类型与目标计算路径 |
| 工作负载 | 输入模态、输入输出长度、并发、预热、重复、质量集版本 |
| 服务指标 | TTFT、TPOT、端到端延迟、P95/P99、吞吐、峰值显存和失败率 |
| 路径证据 | 加载器、计算内核或执行事件、回退原因、状态交接与传输等待 |
| 交付状态 | 失败、降级、恢复、回滚、证据等级与采用决定 |

环境预检、加载成功和单次请求只证明相应阶段可运行。只有固定工作负载下的重复测量、质量检查和路径证据同时完整，结果才能进入部署选型。
