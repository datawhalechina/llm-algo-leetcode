# 02 可重复基线与比较条件

基线保存固定工作负载下的运行条件和结果分布，供后续时间线、性能剖析和候选对照复用。实验开始前先声明要改变的变量；精度或执行后端可以是研究对象，其余条件保持一致。驱动、输入或统计方法意外变化时，应重新采集受影响的基线和候选。

## 固定环境、工作负载与测量过程

先完成环境和输入预检，再执行预热；正式重复运行记录每次结果和失败原因。稳态实验把初始化、编译与预热排除在计时外；冷启动实验则单独规定这些阶段是否计入总时间。

| 条件组 | 必须记录 | 常见错误 |
|:---|:---|:---|
| 环境 | 硬件、驱动、CUDA、框架、执行后端与版本 | 只写 GPU 型号，不记录软件执行路径 |
| 工作负载 | 模型版本、输入/输出长度、批量/并发、数据选择与随机种子 | 基线/候选使用不同输入或请求分布 |
| 测量 | 预热、重复次数、同步点、统计量和超时 | 混用首次运行、稳态结果和主机异步计时 |
| 守护条件 | 正确性、质量、OOM、失败率和 SLO | 只保留最快一次，忽略失败与质量回归 |

## 一份基线至少留下什么

基线记录需要同时保存原始样本、运行条件和质量结果，才能区分策略变化与测量波动。

| 字段组 | 最小内容 | 用途 |
|:---|:---|:---|
| 运行身份 | 模型与版本、硬件、软件版本、后端、精度 | 判断两个结果能否比较 |
| 工作负载 | 输入/输出长度、批量或并发、数据切分、随机种子 | 固定实际负载 |
| 测量样本 | 预热次数、每次耗时/峰值、同步方式、失败原因 | 计算分布并解释异常值 |
| 守护结果 | 正确性、质量、OOM、超时或 SLO | 排除“更快但不可用”的结果 |

## 哪些结果可以直接比较

只有主动改变的候选机制不同，其他会影响结果的条件保持一致时，两个结果才属于同一组比较。下面的判断能防止把环境漂移、请求差异或统计方式变化误读成候选收益。

| 情况 | 能否直接比较 | 原因与下一步 |
|:---|:---|:---|
| 同一模型版本、输入分布、后端、预热与统计协议；仅改变候选策略 | 可以 | 进入时间线、驻留或配对回归分析 |
| 精度或执行后端是预先指定的实验变量 | 可以 | 固定任务、输入和测量范围，分别记录执行栈，并检查质量与实际生效路径 |
| 模型提交、驱动或其他非实验变量意外改变 | 不可以 | 在新的共同条件下重新采集基线和候选 |
| 输入长度、并发或数据切分不同 | 不可以 | 先恢复相同工作负载，或明确比较的是不同场景 |
| 测量过程中出现 OOM、超时或质量失败 | 不能只比较成功样本 | 保留失败原因，并把失败纳入守护判断 |

## 基线如何交给后续任务

执行轨迹、对象驻留和回归判断引用各自对应的基线与候选记录，继承固定条件及声明的变化变量。性能剖析带来的额外开销单独说明，正式延迟对照使用相同的采集设置。

| 后续任务 | 从基线继承什么 | 新增什么 |
|:---|:---|:---|
| 执行轨迹 | 工作负载、环境、阶段定义 | 事件时间线、同步与关键路径 |
| 对象驻留 | 工作负载、环境、预热 | 对象、状态、缓冲区和驻留证据 |
| 性能回归 | 基线分布、失败样本、质量门槛 | 候选分布、阈值和回退判断 |
