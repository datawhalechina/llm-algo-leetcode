# 07 检索切块、索引与增量更新

## 学习问题

用户问“周六能联系支持服务吗”，检索需要找回包含适用日期的内容，而不仅是一个时间数字。文档解析完成后，还要决定切成多大的片段、给片段保留哪些信息，以及文档更新后怎样替换旧内容。

下面沿用教学构造的设备说明：支持服务为周一至周五09:00—18:00，周末不提供；维修申请则通过另一段说明提交。先用词项检索解释文档、片段与索引的关系，再看向量检索多了哪些依赖。

<a id="documents-and-chunks"></a>

## 片段要能独立保留答案依据

切块是把文档划成可单独检索的片段。切得太细，日期与时间可能分离；切得太长，一段中会夹入许多与查询无关的内容，送给模型时也占用更多上下文。可以先沿标题、段落和表格边界划分，再按所用分词器统计长度，对过长内容继续拆分。

说明中的“周一至周五09:00—18:00；周末不提供”适合一起保留，并附上“支持服务”标题。表格转文本时也保留每行的日期与服务条件。相邻片段可以重叠一部分内容，帮助跨边界问题找到依据，但重叠量也会增加索引规模和重复返回，需要随切块规则记录。

| 切块结果 | 保留了什么 | 对查询的影响 |
|:---|:---|:---|
| 只有09:00—18:00 | 时间数字 | 无法判断是否适用于周六 |
| 标题、工作日范围、时间和周末条件 | 当前服务的完整适用条件 | 可为“周六是否提供支持”返回依据 |
| 服务时间和整篇维修流程合为一块 | 更长的原文 | 依据仍在，但需检查无关内容与上下文开销 |

<a id="chunk-provenance"></a>

## 每个片段怎样找回原文

片段编号定位一条可检索记录，文档编号连接同一文档的全部片段，文档版本区分更新前后的内容。再保存标题、页码或段落位置、内容校验值与切块配置，便能查明“这条回答引用的文字来自哪一版说明”。片段编号可以包含文档版本，也可以由其他规则生成；关键是能够识别更新后哪些成员保留、替换或删除。

切块配置变化也可能使所有片段边界变化。例如把每块的最大长度调小，虽然文档正文未变，旧片段与新片段已不再一一对应。此时按照新成员清单重建受影响文档的片段，而不是只比较原文件是否修改。

<a id="retrieval-index"></a>

## 索引怎样帮助找回片段

索引是为查找组织的数据结构。最简单的词项索引记录某个词出现在哪些片段中；收到查询后，按相同的分词规则找出匹配片段，再按所选评分方式排序。第一版练习可以显式给定教学词项，先检查成员和查询结果；真实中文分词、同义表达和排序质量再分别测试。

向量检索先用嵌入模型把片段编码为向量，再检索与查询向量相近的成员。它还依赖嵌入模型及版本、输入处理、向量维度、相似度和索引配置。更换嵌入模型时，文档与查询的编码方式要配套；旧向量是否可继续使用，需要按这些条件检查。向量接近提供候选相关性，回答所需条件是否真的存在，仍要查看返回原文。

<a id="index-update-and-delete"></a>

## 更新和删除要同时影响片段与索引

假设说明A的v2改为“周六09:00—12:00也提供支持”。更新后先生成v2片段，找到v1对应的索引成员并替换，再用原查询检查是否返回新条件。若文档被删除，则从新版本清单移除它的全部片段及可检索引用；只删除原始文件，会留下仍可返回的旧索引内容。

文档、片段和索引按匹配的版本一起切换。新索引构建中断时，继续使用完整旧版，保留候选的处理状态。带删除标记的索引还需确认查询时已经过滤被删除成员；物理文件清理可以稍后完成，查询结果应立即遵守所选择版本的成员清单。

<a id="retrieval-access"></a>

## 查询者可以看到哪些片段

文档限定只能供某个团队查询时，切块后保留相应访问标签，查询时根据当前用户或任务身份筛选可返回的成员。多个团队的文档进入同一索引，也要核对查询结果与缓存是否仍遵守这些条件；给一个无权限的查询返回“相关内容”，会让语义匹配掩盖内容泄露。

检查更新时加入可访问与不可访问两种查询身份，确认标题、片段、引用和日志都按当前范围处理。原文移除或权限变化后，把派生片段和缓存纳入变更检查，再验证新的查询结果。

<a id="retrieval-checks"></a>

## 用固定查询检查哪些变化

先准备独立查询及相关片段依据，选定返回前多少条，再比较切块或索引变化。对于“周六是否提供支持”，查询应能找回包含周末条件的片段；文档更新后应返回新条件，删除后应不再返回该文档。再加入无匹配查询和相似措辞，检查系统是否明确给出未找到，以及关键词变化是否影响召回。参考依据本身可以有多个相关片段，评分规则事先说明怎样计数。

CPU检查优先验证来源保留、完整成员、更新删除和排序确定性。在相同输入与配置下，把增量处理后的查询结果及成员与全量重建比较；并列得分按稳定规则排序。词项检索的这些检查通过后，再选择嵌入模型和真实索引后端，比较召回质量、构建成本与查询时间。生成模型的回答质量则另在固定查询和评分规则下检查。
