# Group 0E: Runtime Diagnostics and Experiment Foundations | 0E: 运行诊断与实验基础

## Group Overview | 组概览

先用 19 检查运行是否有效，再用 17 实际采集 CPU 前向计时与训练阶段事件；18 按对象生命周期估算容量，并用构造的同一时刻分配器数据练习对账；20 固定比较条件，检查失败率、质量与尾延迟。学习时要区分实际采集、理论估算和构造示例，判断每份结果能回答什么问题。

![0E 运行诊断与实验基础路线](../public/00_Prerequisites/0e_debugging_performance_map.svg)

| 层级 | 负责内容 | 不在本层完成 |
|:---|:---|:---|
| Part 00 · 0E | 有效性门槛、时间证据、容量证据、最小单变量实验 | 深度资源归因、具体策略选择 |
| Part 01 · 13 | 算术强度、实际吞吐、实际带宽与暴露等待的资源归因 | 重复讲解基础 Profiler 操作 |
| 性能分析专题 | 时间线、驻留状态、关键路径、瓶颈归因与回归验证 | 直接决定采用哪种优化策略 |
| 性能优化专题 | 根据诊断结果选择、组合并复测候选 | 重复建立基础证据协议 |

| 页面 | 何时进入 | 本节回答的问题 | 带走的证据 |

## Learning Path | 学习路径

### Recommended Order | 推荐顺序

完整学习时按 19 → 17 → 18 → 20 阅读：先建立运行有效性门槛，再学习时间和容量证据，最后把证据组织成可复查的配对实验。文件编号保留原目录顺序，不代表实际诊断顺序。

- 报错、NaN、梯度或质量异常：停留在 [19](./19_Debugging_and_Anomaly_Localization.md)，先定位并复现。
- 运行有效但变慢：19 → [17](./17_PyTorch_Profiling_Basics.md) → [20](./20_Performance_Evidence_and_Experiment_Design.md)。
- 运行有效但容量异常：19 → [18](./18_Memory_Profiling_and_Optimization.md) → 20。
- 需要综合判断：19 → 17 + 18 → 20。

### Next Steps | 后续衔接

- 需要继续学习时间线、驻留状态、关键路径、回归验证与瓶颈归因时，进入[性能分析专题](../topic_discussion/performance_analysis/intro.md)。
- 已取得证据并准备比较优化候选时，进入[性能优化专题](../topic_discussion/performance_optimization/intro.md)。
- 需要从框架记录推导算术强度、实际带宽和资源瓶颈时，进入 [Part 01 · 13 性能分析与瓶颈定位](../01_Hardware_Math_and_Systems/13_Profiling_and_Bottleneck_Analysis.md)。

## Environment Notes | 环境说明

- 17–20 均可在 CPU 上完成证据组织、账本计算和判断练习，不需要为组页单独安装 GPU 环境。
- CUDA 时间、运行时分配器峰值和执行后端证据由后续性能分析、性能优化及相关 Part 02 实验采集；进入具体实验时再使用对应环境说明。
