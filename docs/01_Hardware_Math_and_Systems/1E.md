# Group 1E: Compilation and Backends | 1E: 编译与后端

同一段“矩阵乘 → 加偏置 → 激活”，为什么会有不同的启动次数和中间读写？输入长度变化后，原来的执行路径还能不能复用？本组沿着这条计算链，解释图变换、融合、动态形状和目标后端如何共同影响执行。

## Group Goal | 学习目标

从[09](./09_AI_Compilers_and_Graph_Optimization.md)识别计算图与执行路径，再按问题进入[19 融合](./19_Operator_Fusion_Introduction.md)或[30 形状变化](./30_Dynamic_Shape_Handling.md)；两者是不同分支。若尚未区分框架表达和内核实现，先回看[08](./08_Programming_Models_CUDA_Triton.md)，不必先完成整个执行模型组。在30之后，可按需选读[32 编译阶段与目标计划](./32_TVM_MLIR_Deep_Practice.md)，用Python计划衔接形状、分块和目标能力。

![1E 编译与后端路线](../public/01_Hardware_Math_and_Systems/1e_compiler_hardware_map.svg)

## Learning Entries | 学习入口

| 遇到的问题 | 阅读入口 | 要算清或查清什么 |
|:---|:---|:---|
| 相同计算为什么会使用不同的内核调用与数据路径 | [09 图优化与编译器](./09_AI_Compilers_and_Graph_Optimization.md) | 图变换省去了哪些启动或中间读写，后端还需要什么条件 |
| 中间结果反复写出，融合之后是否更省 | [19 算子融合](./19_Operator_Fusion_Introduction.md) | 内部边界能否消除，有无新增布局转换和资源压力 |
| 输入长度变化，缓存和填充开销随之改变 | [30 动态形状](./30_Dynamic_Shape_Handling.md) | 形状种类、缓存复用、填充数量和路径切换分别怎样变化 |
| 想继续理解目标计划怎样形成 | [32 编译阶段与目标计划](./32_TVM_MLIR_Deep_Practice.md)（进阶） | 同一矩阵的形状、分块、能力与阶段内容是否一致 |
