# Group 2.6: Inference Execution and Generation Acceleration | 2.6：推理执行与生成加速

本组从模型前向的计算执行进入单请求生成，再比较投机式生成的不同候选拓扑。注意力、稠密前馈和专家执行可以按目标选择；学习重点是区分一次前向、单步词元选择和草稿验证。

## Learning Path | 学习路径

### Recommended Order | 推荐顺序

- 执行路径：注意力选 20，稠密前馈与归一化选 `INF-EXECUTION-DISPATCH`，专家层在 [MoE 路由](./06_MoE_Router.ipynb) 后进入 `INF-MOE-EXECUTION`；按计算瓶颈选择，不要求依次完成全部分支。
- 生成路径：21 → 23，先固定单步解码和精确验证语义。
- 草稿分支：35 / `INF-EAGLE` / `INF-PARALLEL-DRAFTING` 并列学习，再由 `INF-PROPOSAL` 统一候选预算和净收益。

### Next Steps | 后续衔接

- 多请求的 KV 状态、动态批次与阶段调度进入 [2.7](./2_7.md)。
- 原生 MTP 先使用 [35 的 Step 5](./35_Multi_Token_Decoding.ipynb)检查配对模型与专用后端；比较投机机制的完整收益时进入 [68](./68_Speculative_Decoding_Benchmark.ipynb)，以实际支持的模型和后端分支为准。

## Environment Notes | 环境说明

- Step1–4 默认使用 CPU 建立机制和状态不变量。
- 单卡实验使用已登记的机制 Profile。专家执行比较固定随机权重的真实 SwiGLU 层，形成局部执行证据；合成 logits 或容量公式不代替真实生成与服务性能。
