# Group 2.7: KV Cache and Serving Systems | 2.7：KV Cache 与 Serving 系统

多个请求同时生成时，历史K/V会持续占用显存，新请求也在等待执行。本组先看KV Cache怎样表示、分配、回收和跨请求复用，再看服务系统怎样选择一轮要处理的请求，并安排提示处理、逐词元生成与设备间的数据传递。

## Learning Path | 学习路径

### Recommended Order | 推荐顺序

- KV 路径：请求状态 → `ARCH-MLA` → 22 → 37 → 24 → 34；54 的 KV Cache 量化作为压缩分支按需进入。
- Serving 路径：`INF-ITERATION-BUDGET` → 36 → `INF-CONTINUOUS-BATCHING` → 38 → `INF-SERVING-OVERLAP` → 39。
- 调度根据可用容量选择请求，缓存管理负责分配和回收，两者分别见36与37。需要比较MoE注意力与前馈拆分、或两侧资源需求不同时，再进入INF-AFD。

- 权重、激活和 KV 压缩进入 [2.8 量化与低比特适配](./2_8.md)；通信与模型切分进入 [2.9 通信与并行](./2_9.md)。

检索增强生成（RAG）先找回资料，再把相关片段放入模型请求。[切块与索引更新](../topic_discussion/data_engineering/07_retrieval_chunks_and_index_updates.md)解释怎样保留文档来源、更新片段并控制可访问内容；本组的KV Cache保存模型计算出的历史状态，复用时检查历史前缀与模型配置。比较执行性能前，再按[请求负载说明](../topic_discussion/data_engineering/08_evaluation_workloads_and_calibration.md)固定实际输入、长度与到达方式。

## Environment Notes | 环境说明

- CPU练习用于回放请求事件，检查缓存分配回收、批次变化和调度结果；运行条件见各机制页的“运行环境”。
- 真实服务测量按[推理优化Quickstart](../topic_discussion/inference_optimization/quickstart.md)选择环境，固定模型版本、请求清单、并发、词元预算、缓存策略和执行后端，再比较延迟、吞吐、失败率与缓存占用。测量入口见69、70与81的实验配置。
